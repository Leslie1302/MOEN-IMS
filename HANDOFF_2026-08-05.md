## WHAT WAS BUILT (by area)

### 1. UI overhaul (institutional / HTMS design language)
- `static/css/index.css` re-themed: forest-green primary, slate nav + tri-color
  Ghana strip, Inter, KPI cards, dark panels. Cache-busted via `?v=` on the
  `<link>` in `base.html` (browsers were serving a stale css).
- Landing (`index.html`): HTMS-style **dark hero** — text left, animated ECharts
  Ghana map right (rippling electrification nodes + transmission lines), reusing
  the app's local `echarts.min.js` + `geojson/ghana_regions.json`. Nav brand is
  the Ministry crest (not the "M" placeholder).
- Dashboards/pages re-skinned green; off-brand purple/blue gradient headers on
  Ghana map / project dashboard / transport status / boq single edit greened.
- **NES Projects Dashboard** (`project_management_dashboard.html`, renamed from
  "SHEP & Electrification"): Strategic Roadmap (real projects as Gantt bars),
  Portfolio Health donut (On-track/At-risk/Delayed derived from planned_end_date
  vs progress), Delivery Trends (materials received + connections energised, two
  series), Regional Distribution. Over-issuance pulled out of the stacked bar
  into its own alert tile; package chart got an All/Active/TBD status toggle.

### 2. Access rate + community progress
- Map headline + regional choropleth now read **real data**: national from the
  seeded config (89.13%), each region from its RegionPopulation baseline.
- **Completion top-up** (`services/access_rate._completion_connection_topup`):
  a community marked Energised/Commissioned credits its BoQ connection target
  (max(0, target − meters)); "target now, meters refine". Fully additive — 0
  when no target, so the national path and old tests are unaffected.
- **Community progress now runs off status, not BoQ targets.**
  `recalc_site_progress_percent` uses the 5-stage % only when a community has
  frozen targets; otherwise falls back to a works_status stage percent
  (Planned 0 / In Progress 50 / Energised 90 / Commissioned 100). This fixed the
  empty progress page (the recalc had been forcing progress to 0 with no targets).
- Map "Completed Communities" count now reflects works_status
  (Energised/Commissioned), not BoQ `status`. Ghana map page relabelled
  "Sites"→"Communities"; methodology note corrected.

### 3. Package-level contract model (contracts are per PACKAGE, not per community)
- **Community is OPTIONAL** on BoQ upload and ReportSubmission; `package_number`
  is the required reconciliation key. `ReportSubmission.create_or_update_boq`
  now carries region/district/community through (it was dropping community).
- **Package Reconciliation page** (`/boq/reconciliation/`,
  `PackageReconciliationView`) styled like the overissuance summary: per-package
  contracted vs received, over/under flags, line breakdown. Linked from the BoQ
  page. (Header text forced white — global h5 rule was darkening it.)
- BoQ Excel **template reworked** (DownloadBoQTemplateView): community optional,
  package_number = reconciliation key.
- `audit_boq_blanks` command repointed to flag blank **package_number/region**
  (community informational only).

### 4. BoQ filters (were broken)
- The BoQ table had two filter systems fighting: server-side header dropdowns +
  `table-utils.js` client filter (page-scoped). Removed `enhanced-table` from the
  BoQ table (`data-no-enhanced`), leaving server-side filtering + Django
  pagination. Fixed the custom filter's selector bug (`.filter-arrow` → the `th`
  with `data-column`), the **plural→singular param mismatch** (`regions`→`region`),
  and styled the invisible white-on-white **Confirm button green**.
- Stock dashboard, Site Progress, Community Progress tables put on the
  `enhanced-table` auto-init (paginate at 25); `data-no-enhanced` is now honoured.

### 5. Performance grades page (was always "0 users")
- `compute_roster` wraps each user in try/except (one bad user no longer zeros
  the roster) + added its missing `logger`. `dashboard_views` now has a
  fail-safe: if the roster is empty it lists active users ungraded with an
  explainer naming the five gradable groups. Empty state reworded honestly.
- Note: `Stores Management` is NOT in GRADABLE_ROLES — those staff aren't scored.

### 6. Area-based scoping (NEW spine)
- `Area` + `AreaRegion` group whole regions; `Profile.area` assigns a user.
- Scope helper `Inventory.utils.accessible_region_names` / `scope_qs_by_area`:
  None (all) for superuser/management; the area's regions for **consultants +
  schedule officers**; **[] (nothing) if a scoped user has no area — fail closed**.
  Store officers are NOT scoped (per the user's choice).
- Applied to: BoQ list, BoQ filter-options endpoint, package reconciliation,
  overissuance summary, community progress, site progress.
- Admin: Area page (with AreaRegion inline); `area` list-editable on Profile.
- **The 10 areas** (seeded, cover all 16 regions, no overlap): Ashanti ·
  Greater Accra+Eastern · Ahafo+Bono+Bono East · Volta+Oti · Central ·
  Western+Western North · Upper East · Northern+Savannah · North East · Upper West.
- **Data rule:** each region must belong to exactly one area, or consignee
  resolution becomes order-dependent. (A uniqueness guard on AreaRegion.region
  was offered but not built.)

### 7. ProjectConsultant reframed onto areas
- `ProjectConsultant.area` FK; consignee resolution binds by **area first**
  (community region → area → that area's consultant), region/district kept as
  legacy fallback. Admin surfaces area as primary. Assign one consultant per
  area, replacing per-region rows.

## KEY DECISIONS (do not relitigate)
- **Contracts are per package; progress is per community (field status).**
  Community optional on contracts; reconcile at the package; community progress
  from works_status + milestones, not contract quantities.
- **Areas are the spine** for both data visibility (Profile.area) and consignee
  routing (ProjectConsultant.area).
- **Go live capturing releases now**; reconcile the contract side live as BoQ
  lands (no pending-release "hang" mechanism needed — register communities first,
  which is cheap). Off-BoQ releases stay warn-but-allow at launch.
- **QGIS**: not adopted for map rendering (GeoJSON + ECharts reads live data;
  QGIS is worse for continuously-changing data). Possible future use: one-off
  desktop name-matching against GSS shapefiles.
